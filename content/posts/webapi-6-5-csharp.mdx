Hay un detalle importante en tu diseño: `ActivityQuestion` tiene una propiedad de navegación `Question`, y su identificador se obtiene mediante `Question.Id`:

```csharp
public Question Question { get; private set; } = null!;

public Guid QuestionId => Question.Id;
```

Esto significa que `QuestionId` es una propiedad calculada, no una propiedad persistente convencional. Vamos a indicarle expresamente a EF Core que la columna de relación es `Question.Id`, utilizando la navegación `Question` y sin intentar mapear `QuestionId` como columna independiente.

## 1. Configuración de ActivityQuestion

Crea el archivo:

`AcSoft.Infrastructure/Persistence/Configurations/ActivityQuestionConfiguration.cs`

## 1. Configuración de ActivityQuestion

Crea `AcSoft.Infrastructure/Persistence/Configurations/ActivityQuestionConfiguration.cs`:

```csharp
using AcSoft.Domain.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace AcSoft.Infrastructure.Persistence.Configurations;

public sealed class ActivityQuestionConfiguration
    : IEntityTypeConfiguration<ActivityQuestion>
{
    public void Configure(EntityTypeBuilder<ActivityQuestion> builder)
    {
        builder.ToTable("ActivityQuestions");

        builder.HasKey(x => x.Id);

        builder.Property(x => x.ActivityId)
            .IsRequired();

        builder.Property(x => x.Sequence)
            .IsRequired();

        builder.Property(x => x.IsRequired)
            .IsRequired();

        // QuestionId es una propiedad calculada del dominio.
        builder.Ignore(x => x.QuestionId);

        // EF Core utiliza una FK de sombra llamada QuestionId.
        builder.HasOne(x => x.Question)
            .WithMany()
            .HasForeignKey("QuestionId")
            .OnDelete(DeleteBehavior.Restrict);

        builder.HasIndex("ActivityId", "Sequence")
            .IsUnique();
    }
}
```

La FK de sombra `QuestionId` permite que EF Core persista la relación sin que tengamos que agregar una propiedad modificable a tu entidad de dominio.

## 2. Configuración de Question

Crea `AcSoft.Infrastructure/Persistence/Configurations/QuestionConfiguration.cs`:

```csharp
using AcSoft.Domain.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace AcSoft.Infrastructure.Persistence.Configurations;

public sealed class QuestionConfiguration
    : IEntityTypeConfiguration<Question>
{
    public void Configure(EntityTypeBuilder<Question> builder)
    {
        builder.ToTable("Questions");

        builder.HasKey(x => x.Id);

        builder.Property(x => x.Code)
            .HasMaxLength(30)
            .IsRequired();

        builder.HasIndex(x => x.Code)
            .IsUnique();

        builder.Property(x => x.Text)
            .HasMaxLength(500)
            .IsRequired();

        builder.Property(x => x.AnswerType)
            .IsRequired();

        builder.Property(x => x.MeasurementType)
            .IsRequired(false);
    }
}
```

Por ahora los enums se almacenarán como números, que es el comportamiento predeterminado de EF Core. Más adelante podemos decidir si conviene almacenarlos como texto.

## 4. Implementar MaintenancePlanRepository

Ahora sí, crearemos el primer repositorio.

Ruta:

`AcSoft.Infrastructure/Persistence/Repositories/MaintenancePlanRepository.cs`

```csharp
using AcSoft.Application.Abstractions.Persistence;
using AcSoft.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace AcSoft.Infrastructure.Persistence.Repositories;

public sealed class MaintenancePlanRepository : IMaintenancePlanRepository
{
    private readonly AcDbContext _context;

    public MaintenancePlanRepository(AcDbContext context)
    {
        _context = context;
    }

    public async Task<MaintenancePlan?> GetByIdWithActivitiesAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        return await _context.MaintenancePlans
            .AsNoTracking()
            .Include(x => x.Activities)
            .FirstOrDefaultAsync(
                x => x.Id == id,
                cancellationToken);
    }
}
```

Aquí utilizamos:

- `Include`: carga las actividades asociadas al plan.
- `AsNoTracking`: evita que EF Core haga seguimiento de las entidades, porque en este caso solo necesitamos consultar el plan.
- `FirstOrDefaultAsync`: devuelve el plan o `null` si no existe.

## 5. Implementar ActivityRepository

Ruta:

`AcSoft.Infrastructure/Persistence/Repositories/ActivityRepository.cs`

```csharp
using AcSoft.Application.Abstractions.Persistence;
using AcSoft.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace AcSoft.Infrastructure.Persistence.Repositories;

public sealed class ActivityRepository : IActivityRepository
{
    private readonly AcDbContext _context;

    public ActivityRepository(AcDbContext context)
    {
        _context = context;
    }

    public async Task<Activity?> GetByIdWithQuestionsAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        return await _context.Activities
            .AsNoTracking()
            .Include(x => x.Questions)
                .ThenInclude(x => x.Question)
            .FirstOrDefaultAsync(
                x => x.Id == id,
                cancellationToken);
    }
}
```

La parte más importante es:

```csharp
.Include(x => x.Questions)
    .ThenInclude(x => x.Question)
```

Esto carga:

1. La actividad del catálogo.
2. Sus asociaciones `ActivityQuestion`.
3. La entidad `Question` relacionada con cada asociación.

Es precisamente lo que necesita `WorkOrder.AddActivity()` para crear las preguntas de la orden de trabajo.

## 6. Actualizar AcDbContext

Tu contexto debe exponer los conjuntos que utilizaremos.

Actualiza `AcDbContext.cs`:

```csharp
using AcSoft.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace AcSoft.Infrastructure.Persistence;

public class AcDbContext : DbContext
{
    public AcDbContext(DbContextOptions<AcDbContext> options)
        : base(options)
    {
    }

    public DbSet<WorkOrder> WorkOrders => Set<WorkOrder>();

    public DbSet<MaintenancePlan> MaintenancePlans =>
        Set<MaintenancePlan>();

    public DbSet<MaintenancePlanActivity> MaintenancePlanActivities =>
        Set<MaintenancePlanActivity>();

    public DbSet<Activity> Activities => Set<Activity>();

    public DbSet<ActivityQuestion> ActivityQuestions =>
        Set<ActivityQuestion>();

    public DbSet<Question> Questions => Set<Question>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);

        modelBuilder.ApplyConfigurationsFromAssembly(
            typeof(AcDbContext).Assembly);
    }
}
```

He eliminado el constructor sin parámetros protegido de tu ejemplo porque no lo necesitamos para la configuración habitual de un `DbContext` mediante inyección de dependencias.

## 1. DependencyInjection.cs

Si utilizas PostgreSQL con Npgsql, quedaría así:

```csharp
using AcSoft.Application.Abstractions.Persistence;
using AcSoft.Infrastructure.Persistence;
using AcSoft.Infrastructure.Persistence.Repositories;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace AcSoft.Infrastructure;

public static class DependencyInjection
{
    public static IServiceCollection AddInfrastructure(
        this IServiceCollection services,
        IConfiguration configuration)
    {
        var connectionString =
            configuration.GetConnectionString("AcSoftConnection")
            ?? throw new InvalidOperationException(
                "No se encontró la cadena de conexión AcSoftConnection.");

        services.AddDbContext<AcDbContext>(options =>
            options.UseNpgsql(connectionString));

        services.AddScoped<IMaintenancePlanRepository, MaintenancePlanRepository>();

        services.AddScoped<IActivityRepository, ActivityRepository>();

        return services;
    }
}
```

¿Qué agregamos?

- `AddDbContext`: registra el contexto de EF Core.
- `UseNpgsql`: indica que utilizaremos PostgreSQL.
- `GetConnectionString`: obtiene la cadena de conexión desde la configuración.
